# Development skills

Store repeatable, project-specific procedures here. A skill should state when it
applies, the commands or tools it uses, the evidence it produces and its failure
boundaries. Skills provide process; they do not grant permissions or hide state.

Put cross-project procedures under `shared/` and register them in
`.agents/content-registry.yaml`. Keep project-specific workflows at the skills
root or in a named project subdirectory; do not copy them into another project
without adapting paths, commands and acceptance evidence.
