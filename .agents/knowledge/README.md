# Development knowledge

Put facts that can change here: machine capabilities, dependency versions,
provider behavior, benchmark baselines and external service details. Date each
fact, name its source and remove or update stale entries instead of presenting
them as current.

Knowledge is normally project-specific. Reuse it across projects only when the
registry marks it `shared` and its source is still valid; machine paths,
providers, versions and benchmarks usually require a new local entry.
