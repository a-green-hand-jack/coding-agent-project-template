# Harvest 2026-10-23, released in v0.1.16

## Decision

The run classified every delta from the recorded watermarks to the scanned
commits and released three shared rules in v0.1.16: files left on the host
belong to the running user (#79), a scriptable fake screens a boundary's failure
paths before a real run (#80), and speed, parallelism and efficiency
optimization are defaults set by measurement (#78). The supervision-by-progress
and follow-up-message items had already landed in #77 and are part of the same
release. All of it is additive shared text plus three memory files and three
registry entries; the upgrade from v0.1.15 is command only.

## Why

The set holds six projects and one derived template; two further projects carry
the marker but are delivery copies of another adopter (one origin), and five
projects made from the derived template are that template's adopters, not this
one's. Two adopters independently required files left on the host to be owned by
the running user; two built scriptable fakes at different boundaries (a provider
HTTP upstream with a stand-in agent, and a fake agent executor driving the public
CLI); one supplied the concurrency and repeated-work measurements that the
maintainer then made the template's default. Everything else was project-local,
already upstream, or drift.

## Apply

- Held watch items (one adopter each) stay in the run report: concurrency
  measurement (now general by maintainer decision), external-tool configuration
  fidelity, the provider catalogue, batch-release leak checks, the journal and
  resume/retry architecture, and a committed agent permission allowlist.
- Drift: one adopter's registry pin is one release behind its shared text, noted
  on its open upgrade request; three projects and the derived template are behind
  with open requests.
- Requests opened or updated in this release round ask three adopters to upgrade
  to v0.1.16; the other open requests still target v0.1.15.
