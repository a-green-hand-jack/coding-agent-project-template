# Downstream harvest before v0.1.12, 2026-10-19

## Decision

- Four adopters moved since the last check (about 260 commits in total); one had not moved.
  Their deltas were read with `gh api` only. No local checkout was scanned.
- Three candidates became shared changes (#59): a lesson from one adopter's data loss when a
  move's source was already a symlink to its destination (a shared record); credentials
  passed through the environment instead of command-line arguments (a rule in
  `llm-credentials`); and one adopter's class of small changes made directly in `dev`,
  which the maintainer also landed in `AGENTS.md` and `DEV.md`.
- The maintainer decided adopters are inspected and contacted through GitHub only, so
  `template-harvest` was rewritten for that and the local state is keyed by repository.
- Not shared, by evidence: a team-mirror remote record that two adopters wrote on the same
  day (their own infrastructure), an adopter's task-routing rules for its own roles, Docker
  naming (already covered by #54), and benchmark, execution and domain product memory.

Adopter names, repositories and private decisions stayed in the ignored local state.

## Why

The release checklist requires a harvest before each release.

## Apply

Start the next run from the recorded watermarks, using the GitHub helpers in
`template-harvest`. Adopters pinned below v0.1.12 take it through `template-upgrade`;
the maintainer upgrades them when wanted.
